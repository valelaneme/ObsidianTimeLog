# 时间日志（TimeLog）

一个极简安卓录入器：把时间记录快速追加到 Obsidian 每日 md、保存前校验重叠、看当天统计。数据始终是你的 md 文件，不锁在 App 里。

> 📌 完整设计（含未来周/月/年方案、冷热数据、快照）见 [DESIGN.md](DESIGN.md)。本 README 只描述**当前代码实现了什么**。

## 当前版本（v1.7.0 · 顶栏左侧菜单+右侧回到今天；滑前预加载、滑到即切换；今天不再往明天滑；主文件拆分）

**设置页**（v1.3）：首页右上角**只有三条横线的图标**（不带文字）进设置页，里面选日记文件夹、重新读取、清除授权、改倒计时默认分钟数。首页不再放"选择文件夹 / 刷新"两个按钮——**刷新全自动**：打开 App 读一次、在设置页选完文件夹回来读一次、从 Obsidian 或别的 App 切回来也读一次（在 Obsidian 里改过 md，回来立刻看到最新）。清除授权只取消 App 的访问权限，不删除任何 md 文件。

**顶栏就一行**（v1.6）：正中间是「录入日期：2026-11-19 ▾」，**点它弹一个小日历，点哪天就立即切到哪天并关掉**（没有"确定/取消"按钮，默认停在你正在看的那天、显示当月，未来日期灰掉）；右上角是三条横线的菜单图标。原来的 `‹ ›` 左右切换按钮和下面的"当前文件夹"小字都已删除（文件夹在设置页里看），翻日期只靠**左右滑动**或点日期选。

**v1.6.2 细节**：①右上角图标改成**三条横线**（汉堡菜单）；②顶栏日期点开是一个**纯日历窗口，没有确定/取消按钮**——点某天立刻切过去并自动关窗，点外面或按返回键可关掉；③录入面板右上角按钮从 `×` 改成**「返回」**，点了回到录入日期页面；④**正计时、倒计时**自动弹出录入面板时，日期一律填**真实的今天**，不再跟着首页正在看的那天走（手动点「录入」时仍按首页日期，方便补记旧日志）。

**界面**：打开就是**当日分析首页**（昨天/今天随便翻）。屏幕**底部固定三个大按钮**，单手握手机拇指就够得到：

| 按钮 | 作用 |
|---|---|
| ⏱ 正计时 | 点一下开始（记住开始时刻），忙完再点一下 → 时间段自动填进录入框。**锁屏、切到微信都不影响**，因为记的是时间点不是累加秒数。 |
| ✎ 录入 | 从底部弹出一个**最多半屏的录入面板**，浮在分析页上；下滑顶部的把手或点「返回」或点面板外都能收起。 |
| ⏳ 倒计时 | 输入分钟数 → 到点**弹手机通知**，关掉 App、锁屏也照弹。点通知会回填时间段。默认分钟数在**设置页**改（整数），点倒计时时自动预填上次用的数。 |

**保存前校验**：点"校验并追加"时，先检查新时间段和当天已有记录是否重叠。有重叠弹窗告诉你和哪条重叠、多少分钟，你可以**返回改时间**或选择**仍然保存**——不会再默默写进一条冲突记录。

**录入提速**：日期默认当天；起止时间旁有"现在"，下面还有"开始整点 / 结束整点 / 结束半点 / 清空"；一级/二级分类、事项、双链记住上次填过的；边填边预览要写入的那一行。

**常用一键选**（v1.2）：App 首次打开时扫一遍日记目录，把历史日志里最常用的一级分类、二级分类、双链（各前 10 个）做成小按钮显示在对应输入框下面，点一下就填；双链再点一下可取消。只统计、不改动你的 md。

**连续录入**（v1.2）：录入面板底部勾选"保存后继续录下一段"，保存后浮层不收起，开始时间自动接上一段的结束时间（跨午夜自动跳到次日），适合一口气补多条。

**跨午夜**：结束早于开始时按 24 点拆成两行写进两天（如 `23:50-24:00` + 次日 `00:00-00:20`）；结束正好 00:00 只写当天一段。跨午夜保存时会连次日文件一起查重叠，不会漏检。

**录入日期页**（v1.4，原来是"单日分析"）：标题显示当前查看的日期，**左右滑动屏幕就能翻前一天/后一天**（左滑往后、右滑往前；慢速划也算——横向位移 ≥40dp、明显比纵向多即可，不再要求甩的速度；录入面板展开时不响应）。**最远只到今天**——未来还没发生，往后滑会提示"今天就是最新的一天了"，日历里未来的日子也是灰的。翻的时候是**微信切标签那种整页滑动**：先把当前页面拍成一张图（快照）叠在内容区上，旧页滑出、新页从另一侧滑入，两块一起动，260ms 结束；只有拍照失败时才退回小幅滑入兜底。快照只在切日期时生成一次，不参与布局计算。顶部 **24 小时时间轴**：灰色是未记录，彩色按一级分类区分，顶部红条是重叠，蓝线是当天当前时刻；**3/6/9/…/21 点的刻度是几条黑色细竖线，直接画在色带上**（最后绘制，压在任何颜色之上，不会被盖掉），不再占下方空间，所以整条色带只有 20dp 高，主角留给记录列表。下面**四项统计排成一行**：记录时间 / 未记录 / 覆盖率 / 记录条数；再下面一行是一级分类的时长与占比。**总记录时间**按区间并集算（重叠不重复计），未记录 = 24 小时 − 总记录时间，两者相加恒为 24 小时。

**当天记录，点一下就能改**（v1.4）：每条记录压成一行（时间段 + 时长 + 分类 + 事项 + 双链 + 备注），左侧色条按一级分类上色。**行高严格等于字号的 2 倍**（13sp 字 → 26sp 高），上下不再额外留白；两条记录时间接不上时中间留半行高的空档并标出空了多久。**行上不再有删除按钮——点这一行会打开录入面板并自动填好原来的值**，改完点"保存修改"就**替换原来那一行**（不是新增），保存前同样会做重叠校验。删除按钮移到了录入面板里（只有点记录进来编辑时才出现）。

**时间写坏的行会标红**（v1.5）：解析不出来的行不再只是文字提示，而是**红底红字排进记录列表最后**（形如「第 12 行 时间数字不合法：==25:00 - 26:00== ...」）。**点它就把能认出来的字段（日期、时段、分类、事项、双链、备注）预填进录入面板**，改好保存即替换原来那一行；面板里也有「删除这条记录」，可以整行删掉。判断口径：
- 有 `==` 或像时间（`9:00`）但格式/数值不对 → 标红提醒
- 完全没有时间样式的普通待办（`- [ ] 买牛奶`）→ 不是时间记录，**不打扰**
- 只有文件级问题（没选文件夹、文件名没日期）才留在上方的「提示」块，没有就整块隐藏

**重叠校验**：有重叠才显示，没重叠整块隐藏，不占地方。

**当天全部记录**（v1.3）：统计下方按时间顺序列出当天**每一条**记录（时间段、时长、一级/二级分类、事项、双链、备注）。两条记录时间没接上时，中间留**半行高的空档**并标出空了多久，一眼看出漏记的时段；时间连得上就紧挨着排。每条右侧有"删除"，确认后只从 md 里删掉那一行（跨午夜的记录会整行删，含前一天那一段）。

**写入按时间排序**（v1.3）：新记录不再一律追加到文件末尾，而是按开始时间插进当天 md 的正确位置；标题、正文、空行等其它内容保持原位不动。

**周 / 月 / 年分析**：后续版本加入。底层已把"单日小计"做成可聚合的数据原子，加周/月分析不用改录入和解析代码。

## 它认什么格式

文件名必须是日期，例如 `2026-11-19.md`。文件里只认这种行：

```
- [ ] ==00:00 - 05:30== [[○ 睡觉]] [[♺ 晚睡]] **-** 昨天睡的很早，感觉起来还是不精神。
- [ ] ==05:30 - 06:10== [[○ 家务]] [[♺ 做饭]] **早餐** 做了什么 [[地点]]  [[任务]]
```

规则：以 `- [ ]` 或 `- [x]` 开头；时间段写在 `== ==` 里；`[[○ 分类]]` 是一级，`[[♺ 分类]]` 是二级；`**事项**` 里写 `-` 表示没有事项名。其他文字当备注，`[[地点]]` 这类链接只存不算。

## 三个口径（写死在代码里）

1. **睡眠计入统计**：总时长和分类占比都包含睡眠，不剔除。
2. **跨午夜按实际时间切两天**：例如 `23:00 - 01:00`，当天记 `23:00-24:00`，次日 md 记 `00:00-01:00`。
3. **覆盖率含睡眠**：覆盖率 = 当天实际覆盖分钟 ÷（天数 × 24 × 60），重叠不重复计。一天记满才 100%。
4. **总记录时间按区间并集算**（v1.3）：重叠的时间只算一次，所以「总记录时间 + 未记录时间 = 24 小时」恒成立。覆盖率与分类占比仍按各条累加（有重叠时会略高，界面会另行提示）。

## 怎么用（手机上）

1. 打开 App，点右上角**三条横线** → **选择日记文件夹**，选中 Obsidian 日记目录（放 `2026-11-19.md` 的那个文件夹），允许访问。**回到首页会自动读取**，之后每次打开 App、从 Obsidian 切回来也都会自动刷新，没有任何手动刷新按钮。首次会问通知权限，选允许（倒计时要用）。
2. 首页看当天统计、时间轴和「当天全部记录」；**左右滑动**翻日期（只能翻到今天），或**点顶栏的日期**弹日历选一天。两条记录之间若留出空档，说明那段时间还没记。
3. 记录一段：点 **正计时** 开始 → 忙完再点一下 → 点 **录入** 弹出面板，时间段已填好 → 补分类/事项 → 点"校验并追加"。有重叠会弹窗让你确认。
4. 或直接点 **录入** 手动填；点起止旁的"现在"或下面的整点/半点按钮；常用名字直接点输入框下方的小按钮。手改日期后点"查看"，首页统计会跟着切过去。
5. 要连着补几条，先勾上"保存后继续录下一段"，每段保存后开始时间会自动接上一段。
6. 定时一段：点 **倒计时** 输分钟数 → 到点通知 → 点通知回填时间段。再点倒计时按钮可取消。

录入这一步也可以继续用你现有的 MacroDroid，App 只用来计时和校验——两套写入格式一致即可。

## 代码结构（便于以后加功能）

```
core/   纯 Kotlin，不依赖 Android，可单独测试
  Models.kt       数据模型，核心是 DaySummary（单日小计，可聚合）
  LogParser.kt    把 md 一行解析成 LogEntry（跨午夜拆两天）+ timeOfLine(写入排序用)
  LogFormatter.kt 把录入字段拼成 md 行（与 Parser 严格对称）
  Analyzer.kt     analyzeDay + combine(周/月/年聚合) + overlaps + coveredMinutes(区间并集)
data/   Android 数据层
  VaultRepository.kt  SAF 授权、loadDay(只读当天)、loadSuggestions(历史词频)、按时间插入写入、deleteEntry
  Prefs.kt            记住上次录入 + 计时状态（存绝对时刻，切走也准）
ui/TimelineView.kt   24 小时时间轴（纯 Canvas 绘制，无第三方图表库）；分类配色对外复用
SettingsActivity.kt  设置页：选择文件夹 / 重新读取 / 清除授权
MainActivity.kt   只做 UI 编排：首页/设置入口/三按钮/浮层/当天记录列表/校验弹窗/计时
TimerReceiver.kt  倒计时到点的系统闹钟接收器，弹通知
```

加周/月分析时：读那几天的 DaySummary，调用 `Analyzer.combine()` 聚合即可，不需要新的分析逻辑。

## 怎么打包安装（本机没有 Android Studio，用 GitHub 云端编译）

1. 把代码传到 GitHub（网页版新建仓库 → upload files → 拖进去 → Commit changes）。
   - ⚠️ `.github` 是隐藏文件夹，Windows 拖拽容易漏传。漏了它 Actions 就不会自动跑；此时可点 **Actions** 页手动 **Run workflow** 也能编译（前提该 workflow 已在仓库里）。
2. 点 **Actions** → 左侧 **Build APK** → **Run workflow** → 点绿色按钮。
3. 跑完有两种拿包方式：
   - **推荐：Releases 直下 .apk**（不用解压）→ 回仓库首页，右侧 **Releases**（或直接打开 `/releases/latest`）→ 点开最新一条 → 在 **Assets** 里点 `Timelog-1.7.0.apk` 即直接下载 APK 文件。**文件名就是版本号**，下载下来就是 `.apk`。
   - 或用 **Artifacts**：点进这次运行 → 最下方 **Artifacts** → 下载 **Timelog-1.7.0-zip**。注意 GitHub 的 Artifacts **一定是 zip**（平台机制，无法改成直接给 apk），解压后得到 `Timelog-1.7.0.apk`。
4. APK 传到手机安装（允许"安装未知来源应用"）。首次打开选一次日记文件夹授权 + 通知权限。

**版本号**：现在分成两个，各管各的（v1.6.1 起）：

| 字段 | 谁会看到 | 怎么来 |
|---|---|---|
| `versionName` | APK 文件名、Release 标签、手机「应用信息」里显示的版本 | **手写**，在 `app/build.gradle` 顶部的 `def appVersionName = '1.7.0'` 改这一行；发新版就改成 `1.7.0` |
| `versionCode` | 只有安卓系统内部用，手机上不显示 | 编译时刻的分钟级时间戳，**每次编译必然变大**，所以覆盖安装不会被系统当成同一版本而"装了没反应" |

Gradle 会把本次 `versionName` 写到 `app/build/timelog-versionName.txt`，workflow 据此把 APK 改名为 `Timelog-1.7.0.apk`、发 Release `v1.7.0`（标题 `TimeLog 1.7.0`），所以**文件名、Release 标签、手机里显示的版本号三者永远一致**。最低 Android 8.0（API 26）。

## 正式签名（已接好）

GitHub 仓库 → Settings → Secrets and variables → Actions 里已存这 4 个 Repository secrets：

| Secret | 作用 |
|---|---|
| `KEYSTORE_BASE64` | 签名密钥文件（.jks/.keystore）转成的一长串 base64 文本 |
| `KEYSTORE_PASSWORD` | 密钥库密码 |
| `KEY_ALIAS` | 密钥别名 |
| `KEY_PASSWORD` | 该别名的密码 |

光把值存进 GitHub 还不够，代码里要有"取钥匙 → 用它签名"的步骤，这次已补上：

- `.github/workflows/blank.yml`：编译前把 `KEYSTORE_BASE64` 解码成临时 keystore（放在仓库目录之外，用完即弃，不进代码库），并把 4 个值传给 Gradle；编译后新增 `Verify APK signature` 一步，签名不对就直接报错，不会让你下载到装不上的包。
- `app/build.gradle`：4 项齐全才启用正式签名，**debug 和 release 两个构建都用同一把钥匙**；缺任意一项自动回退系统默认调试签名，保证换个环境也能编出能装的包。编译日志里会打印 `TimeLog: 使用正式签名` 或 `TimeLog: 未检测到签名配置`，方便一眼确认。

> ⚠️ **第一次装正式签名包，必须先把手机上旧的 TimeLog 卸载掉**。之前装的是系统临时调试密钥签的包，签名换了，安卓不允许直接覆盖（会报"应用未安装 / 签名冲突"）。卸载这一次之后，以后每次覆盖安装都正常。
>
> 卸载前不用备份数据——你的日志是 Obsidian 里的 md 文件，不在 App 里；重装后重新选一次日记文件夹授权即可。

产物命名：APK 编译后改名为 `Timelog-<版本号>.apk`（当前 `Timelog-1.7.0.apk`），同时上传 Artifact（GitHub 会包成 zip，名字 `Timelog-1.7.0-zip`）和发布 Release（`v1.7.0`，Assets 里是原始 .apk 直链，不用解压）。**同一个版本号重复编译时，会覆盖 Release 里同名的那一个文件**，链接不变。构建类型仍是 debug；以后要出正式发布版，把 workflow 里 `assembleDebug` 改成 `assembleRelease`、上传路径改成 `.../apk/release/app-release.apk` 即可，签名配置不用再动。

## 已知限制与风险

- **本机没有 Android SDK，无法实编译**。代码已做静态检查（括号配平、控件 ID 与代码引用完全对齐、无旧符号残留、权限声明一致），并用真实数据验证过"生成→解析→聚合""保存前重叠校验"全链路。GitHub Actions 首次运行若报错，把红色日志原文发我即可定位。
- **正式签名已通过云端编译验证**（用户确认）。以后若换密钥，在 `Build APK (signed)` 日志里找 `TimeLog: 使用正式签名`；出现 `未检测到签名配置` 说明 Secrets 没传进来，报 `keystore`/`alias`/`password` 多半是某个 Secret 的值和密钥文件对不上（别名、两个密码别填反）。`Verify APK signature` 通过才算真的签上了。
- **精确闹钟**：Android 14+ 把"精确定时"列为特殊权限，需你在系统设置里给本 App 开一下"闹钟和提醒"；不开也能响，只是可能晚几分钟（代码会自动降级）。红米若省电策略拦截，把本 App 设为"无限制"。
- **通知权限**：Android 13+ 首次会问；拒绝后倒计时到点不弹通知，需在系统设置里补开。
- 日历只读当天对应的 md（加前一天跨午夜落到当天的一条），**不递归子目录**。按年归档进子文件夹的旧日志当前读不到——这正是 DESIGN.md 冷热分层方案要解决的，后续版本实现。
- 二级分类留空时，统计归入"（未填二级）"。
