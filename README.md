# 时间日志（TimeLog）

一个极简安卓录入器：把时间记录快速追加到 Obsidian 每日 md、校验当天重叠、看当天统计。数据始终是你的 md 文件，不锁在 App 里。

> 📌 完整设计（含未来周/月/年方案、冷热数据、快照）见 [DESIGN.md](DESIGN.md)。本 README 只描述**当前代码实现了什么**。

## 当前版本做了什么（v1 · 单日版）

- **快速录入**：日期默认今天；起止时间旁有"现在"按钮一键填当前时刻；一级/二级分类、事项、双链会自动记住上次填过的，下次打开直接带出；边填边预览要写入的那一行。
- **跨午夜处理**：结束早于开始时，自动按 24 点拆成两行、写进两天的 md（如 `23:50-24:00` + 次日 `00:00-00:20`）；结束正好是 00:00 时只写当天一段，不留 0 时长的空行。
- **当天重叠校验**：只看所选日期，列出重叠区间和重叠分钟数。
- **单日统计**：当天总时长（含睡眠）、覆盖率（分母 24 小时）、一级/二级分类时长占比、重叠数。点 ‹ › 翻到任意一天。

**周 / 月 / 年分析**：界面上已留位置，按计划在后续版本加入。底层已把"单日小计"做成可聚合的数据原子，加周/月分析时不用改录入和解析代码。

## 它认什么格式

文件名必须是日期，例如 `2026-11-19.md`。文件里只认这种行：

```
- [ ] ==00:00 - 05:30== [[○ 睡觉]] [[♺ 晚睡]] **-** 昨天睡的很早，感觉起来还是不精神。
- [ ] ==05:30 - 06:10== [[○ 家务]] [[♺ 做饭]] **早餐** 做了什么 [[地点]]  [[任务]]
```

规则：以 `- [ ]` 或 `- [x]` 开头；时间段写在 `== ==` 里；`[[○ 分类]]` 是一级，`[[♺ 分类]]` 是二级；`**事项**` 里写 `-` 表示没有事项名。其他文字当备注，`[[地点]]` 这类链接只存不算。

## 三个口径（写死在代码里）

1. **睡眠计入统计**：总时长和分类占比都包含睡眠，不剔除。
2. **跨午夜按实际时间切两天**：例如 `23:00 - 01:00`，当天记 `23:00-24:00`，次日 md 记 `00:00-01:00`。
3. **覆盖率含睡眠**：覆盖率 = 记录总分钟 ÷（天数 × 24 × 60）。一天记满才 100%。

## 怎么用（手机上）

1. 打开 App，点 **选择日记文件夹**，选中你的 Obsidian 日记目录（放 `2026-11-19.md` 的那个文件夹），允许访问。
2. **录入** 页：点起止时间旁的"现在"填入时刻；填分类/事项（会自动带出上次的）；下方预览就是将要写入的行；点"追加到当天 md"。
3. **校验** 页：看当天的重叠区间。
4. **单日分析** 页：看当天的时长、覆盖率、分类占比；点 ‹ › 翻其他日期。

录入这一步也可以继续用你现有的 MacroDroid，App 只用来校验和分析——两套写入的格式一致即可。

## 代码结构（便于以后加功能）

```
core/   纯 Kotlin，不依赖 Android，可单独测试
  Models.kt       数据模型，核心是 DaySummary（单日小计，可聚合）
  LogParser.kt    把 md 一行解析成 LogEntry（跨午夜拆两天）
  LogFormatter.kt 把录入字段拼成 md 行（与 Parser 严格对称）
  Analyzer.kt     analyzeDay(单日) + combine(聚合，供周/月/年用) + overlaps
data/   Android 数据层
  VaultRepository.kt  SAF 目录授权、loadDay(只读当天，秒开)、追加写入
  Prefs.kt            记住上次录入的分类/事项/双链
MainActivity.kt   只做 UI 编排，业务逻辑都在上面两层
```

加周/月分析时：读那几天各自的 `DaySummary`，调用 `Analyzer.combine()` 聚合即可，不需要新的分析逻辑。

## 怎么打包安装（本机没有 Android Studio，用 GitHub 云端编译）

1. 把代码传到 GitHub（网页版新建仓库 → upload files → 拖进去 → Commit changes）。
2. 点 **Actions** → 左侧 **Build APK** → **Run workflow** → 点绿色按钮。
3. 跑完点进这次运行 → 最下方 **Artifacts** → 下载 **TimeLog-APK**（zip）→ 解压得到 `app-debug.apk`。
4. APK 传到手机安装（允许"安装未知来源应用"）。首次打开选一次日记文件夹授权。

每次云端编译版本号自动 +1（versionCode / versionName 读 `github.run_number`）。APK 用默认调试签名可直接装；换你自己的正式签名需配 GitHub Secrets（以后需要再加）。最低 Android 8.0（API 26）。

## 已知限制与风险

- **本机没有 Android SDK，无法实编译**。代码已做静态检查（括号配平、控件 ID 与代码引用完全对齐、无旧符号残留），并用真实日志样例跑过"生成 → 解析 → 聚合"全链路验证。GitHub Actions 首次运行若报错，把红色日志原文发我即可定位。
- 编译工作流不用 `android-actions/setup-android`（该 Action 会装已被 Google 移除的旧 `tools` 包而失败），改用 ubuntu 镜像预装的 SDK + `sdkmanager` 补装 platform 34。
- Gradle：AGP 8.2.2 / Kotlin 1.9.22 / Gradle 8.2，compileSdk 34。
- 日历视图只读当天所对应的 md（外加前一天文件里跨午夜落到当天的一条），**不递归子目录**。若日记按年分文件夹归档了，当前版本读不到子目录里的旧日志——这正是 DESIGN.md 里冷热分层方案要解决的问题，后续版本实现。
- 二级分类留空时，统计里归入"（未填二级）"。
